# emby-proxy-alpine-lite

一个面向 **Emby / Jellyfin 反向代理** 的轻量级一键脚本，主打：

- 轻量
- 菜单式
- 多站点共存
- 支持非 80/443 端口
- 支持 Alpine / Debian
- 默认使用 **acme.sh + DNS 验证** 申请与自动续签证书

适合在小内存 VPS、NAT VPS、只能开放高位端口、需要 HTTPS 入口的场景下快速部署。

---

## 功能特性

- ✅ 支持 **Alpine / Debian / Ubuntu**
- ✅ 支持 **DNS 验证签发证书**
- ✅ 默认使用 **acme.sh 自动续签**
- ✅ 支持 **Cloudflare / 阿里云 DNS / DNSPod**
- ✅ 支持 **非标准 HTTPS 端口**
- ✅ 支持 **HTTP / HTTPS 上游**
- ✅ 支持 **WebSocket / 长连接**
- ✅ 支持 **多个站点同时存在**
- ✅ 支持 **BasicAuth** 额外门禁
- ✅ 支持三种反代模式
- ✅ 支持 **Emby / Jellyfin / 自定义** 媒体路径分流预设
- ✅ 支持按编号：查看 / 编辑 / 删除站点
- ✅ 支持按编号：查看站点详情 / 重新签发证书
- ✅ 删除站点时可自动清理对应证书与续签记录（同域名仍被其他站点使用时会自动保留）

---

## 适用场景

适合：

- 自用 Emby / Jellyfin 反代
- NAT VPS / 特殊网络环境
- 无法开放 80 / 443 的机器
- 需要高位 HTTPS 端口入口
- 需要 HTTPS 入口回源到 HTTP / HTTPS 上游
- 希望一台机器托管多个独立反代站点
- 希望用菜单方式维护，而不是手改 Nginx 配置

不太适合：

- 高并发公网流量入口
- 多人同时大规模播放的重度场景
- 企业级高可用集群
- 极低内存下的高负载生产环境

## 三种反代模式

### 1）标准全站反代

适合：

- 只有一个上游
- 所有请求都走同一个 Emby / Jellyfin 服务

效果：

```text
客户端 -> 入口域名 -> 单个上游
```

---

### 2）前后端分离反代

适合：

- 前端 / API 与媒体流不在同一个上游
- 网页、接口和播放流需要分开走不同节点

效果：

```text
普通页面 / API -> 前端上游
播放相关路径 -> 媒体流上游
```

---

### 3）播放流分流反代

适合：

- 默认所有请求都走主站
- 但播放相关路径单独走媒体流专用上游

效果：

```text
默认请求 -> 主上游
播放相关路径 -> 媒体流专用上游
```

## 媒体路径预设

在涉及媒体分流的模式下，脚本支持选择媒体路径规则：

```text
1) Emby（默认）
2) Jellyfin
3) 自定义正则
```

### Emby 预设

适合常见 Emby 路径。

### Jellyfin 预设

适合常见 Jellyfin 路径。

### 自定义正则

如果你的前后端或播放路径较特殊，可以自己输入正则表达式。

## 重新签发站点证书

菜单：

```text
7) 重新签发站点证书
```

该功能用于：

- 证书过期异常
- 证书安装异常
- 想手动重新申请一次证书

流程是：

1. 按编号选择站点
2. 重新选择 DNS 提供商
3. 重新输入 DNS API 信息
4. 重新申请并安装证书
5. 检查并重载 Nginx

### 自动续签说明

本项目默认使用：

- `acme.sh` 申请证书
- `acme.sh --install-cert` 安装证书
- `reloadcmd` 自动重载 Nginx

也就是说：

- **默认自动续签始终保留**
- 手动“重新签发站点证书”只是额外主动触发一次
- 不会关闭或破坏自动续签机制

## 删除反代站点

菜单：

```text
3) 删除反代站点
```

当前删除站点时会：

- 删除对应站点配置
- 删除对应 BasicAuth 文件
- 检查同域名是否还有其他站点在使用

### 如果该域名没有其他站点使用
会继续：

- 删除该域名证书目录
- 删除该域名在 `acme.sh` 中的续签记录

### 如果同域名还有其他站点在使用
则会：

- 保留证书目录
- 保留续签记录

这样可以避免误删同域名其他端口仍在使用的证书。

## Host 头策略

脚本支持为不同上游选择 Host 头策略，适合这些情况：

- 上游要求 Host 必须等于它自己的域名
- 上游要求保持客户端访问域名
- 上游需要自定义 Host

这对某些 CDN、前后端拆分、特殊源站比较有用。

## 多站点共存说明

本项目支持多个站点同时存在，例如：

```text
https://a.example.com:2053
https://b.example.com:30443
https://c.example.com:52443
```

它们可以：

- 使用不同域名
- 使用不同端口
- 使用不同模式
- 使用不同上游
- 使用不同证书

每个站点都会生成独立配置，例如：

```text
/etc/nginx/http.d/emby-lite-a.example.com-2053.conf
/etc/nginx/http.d/emby-lite-b.example.com-30443.conf
```

或在 Debian / Ubuntu 上：

```text
/etc/nginx/conf.d/emby-lite-a.example.com-2053.conf
/etc/nginx/conf.d/emby-lite-b.example.com-30443.conf
```

证书目录示例：

```text
/etc/nginx/certs/a.example.com/
/etc/nginx/certs/b.example.com/
```

## 轻量化说明

脚本已经做了一些偏轻量的默认设置，例如：

- `worker_processes 1`
- 关闭访问日志
- 菜单式维护，避免引入额外面板
- 使用 Nginx 原生反代，不叠重型依赖

但仍需注意：

- 128MB 适合极低并发、轻量自用
- 256MB 起更稳妥
- 如果是多人同时播放或流量较大，建议更高内存

## 常见建议

### 1. 首次部署尽量先用单站点跑通
先确认：

- 域名解析正常
- DNS API 可用
- 证书申请成功
- 入口可访问
- 播放能通

再继续加第二个、第三个站点。

### 2. 小内存机器优先 Alpine
如果你目标是极限轻量，优先建议 Alpine。

### 3. 尽量避免同机叠太多服务
如果机器内存很小，不建议同机再叠：

- 面板
- Docker
- 数据库
- 监控
- 其他高常驻服务
